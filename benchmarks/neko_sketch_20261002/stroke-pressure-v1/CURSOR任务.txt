任务：验证 Neko 简笔画“单个笔画内粗细变化”的独立笔刷原型。
日期：2026-10-02。只在本压缩包目录测试；不接入 Neko，不改正式配置，不重新跑语言模型，不替换样本，不决定最终选型。

一、要验证什么
用户要的是落笔、行笔、提笔过程中，同一笔内自然改变宽度。
模型负责输出轨迹；这一轮只评估笔刷根据轨迹绘制粗细变化的能力。不能用本轮时间替代中文 prompt 到最终画面的端到端时间，不能用它宣称之前的 3 秒目标已经通过。
cases.json 是冻结的 XY 坐标和笔画顺序，没有真实时间或笔压。所有 pressure-arc 曲线都是设计模拟。不能把点间距离叫作“实际绘画速度”，不能把鼠标默认 pressure=0.5 叫作真实笔压。

二、需要的环境与运行方法
普通云端 Linux CPU 即可。Node.js >=20、npm、Chromium 所需系统依赖；不需要 GPU、PyTorch、模型权重、图片 API 或 Hugging Face token。
解压后进入 stroke-pressure-v1：

  npm ci --no-audit --no-fund
  npx playwright install --with-deps chromium
  npm run check
  npm run build
  node benchmark.mjs --out cloud-results > cloud-benchmark.log 2>&1

先检查每一步 exit code。下载/系统依赖失败就保留错误，标记 not_run；不要制造结果或用其他模型顶替。完整命令是正式测评；--quick 只有 56 次静态请求，只能作为调试，不能和 336 次正式结果合并。
benchmark 自带仅绑定 127.0.0.1 的临时静态服务。要自己看预览，另开终端运行 node server.mjs 50435，再打开 http://127.0.0.1:50435/ 。浏览器运行时仅访问本地文件，不调用在线图片服务。
重跑使用不同输出目录，例如 --out cloud-results-2；不要覆盖、拼接或挑选第一次的记录。

三、四个固定对照
constant：完全等宽，使用与候选相同的填充轮廓引擎。
sketchling：当前 Sketchling 0.6.0，数字 weight=3，looseness=0.13，calm/smooth，实调用 sketch.stroke / sketch.loop / mountRenderable。整笔基本线宽固定，粗糙几何或重叠可能造成视觉厚薄。
pfh-auto：perfect-freehand 1.2.3 的默认点距模拟压力基线，simulatePressure=true、size=3、thinning=0.65。原始点距会影响结果；不是测得的速度。
pressure-arc：先按 1.5 逻辑像素重采样，再沿笔画长度安排压力，构造变宽的实心轮廓。长笔轻入/加力/提笔，短笔减小变化，闭合笔采用周期曲线避免首尾宽度接缝。全部笔压为合成数据。
固定相同输入、笔画顺序和基础宽度。候选改变轮廓宽度，不为了某题重画人物或替换图形。PFH 和 Sketchling 的原生平滑/扰动属于对照本身，不额外篡改输入。

四、样本与测量
10 个几何测试：长直线、曲线、圆圈、锐角、交叉、8 字、点、短线、重复点、与长直线相同但点密度不均的轨迹。
4 个旧简笔画冻结样本：拥抱、送花、感谢、伸懒腰。来自 composition-v3 seed17，来源与 SHA 在 cases.json 中；保留原有语义缺陷，只用于笔刷对照。
14 题 × seeds(17/29/43) × 输出分辨率(320/640) × 4 个对照 = 336 次静态请求。
逻辑画布始终是 320×320。640 输出是二倍分辨率，宽度统计需换算为逻辑像素。
先预热 4 次，不计入正式结果。按成功样本计算 p50/p95，必须同时给出请求数、成功、blank、error；不要删掉单点等失败题。
另测 pressure-arc 14 次真实 requestAnimationFrame 播放，设定 1200ms；记录实际首墨、完整可见、帧数与最大帧间隔，不使用事后拼帧的伪时间。
首墨是画布出现灰度<100 的像素后，再等两次 requestAnimationFrame；完整可见也等两次。静态耗时包括本地几何构建和浏览器绘制，不包括语言模型推理。
21 个固定进度帧检查已落墨保留。保留全部灰度 128 阈值丢失数和 before/after 样例；另给强丢失诊断（before<96 且 after>160）。即使只是边缘抗锯齿，也不能把原始丢失数清零。
检查 SVG 导出和 Canvas 最终图的像素一致性，并导出圆圈、交叉、8 字、拥抱的 5 个关键帧，排查未来笔画提前出现。
3 次新建浏览器到静态可见的冷启动，HTTP 服务已运行；不称为“开机冷启动”。
报告 CPU、OS、Node、Chromium、依赖版本和输入 SHA。Node 内存不是浏览器内存，系统内存不是显存。不能测的峰值保持 null。

五、候选进入下一轮的条件
自动条件：
1. pressure-arc 全 84 次静态请求非空、无错误、无边缘裁切；没有 NaN/Infinity、交叉处破洞、圆圈闭合缺口。
2. npm run check 全过：单笔宽度明显变化；相同直线仅改变点密度，候选压力曲线与几何仍相同；闭合笔首尾宽度相同；同 seed 可复现。
3. 320 和 640 的候选几何构建 p95 各 <=50ms；实际首墨 p95 <=200ms；1200ms 播放的完整可见 p95 <=1500ms，最大帧间隔的请求级 p95 <=33ms。云端繁忙导致失败也如实报告。只比较本次同机四个版本，不拿另一台机器数字排速度名次。
4. 原始 lost_dark_pixels 必须报告。严格验收要求全部为 0；若只出现边缘灰度越过阈值，保留为待复核问题，给坐标和灰度差，不能改口为严格通过。
5. SVG/Canvas 最终像素差异为 0。21 个进度帧只是抽样，不能称为所有播放帧的逐帧证明。

人工条件：
自动检查不等于“像人画”。先隐藏版本名，用相同图的四个版本做盲评。评“落笔轻重自然”“转弯/收笔自然”“整体手绘感”各1–5分，并看动画有没有回缩、接缝、香肠状鼓包。
由真实人工填写；未评分留 null。目标：候选手绘感均分>=3.5，落笔/收笔自然均分>=4，并优于等宽对照。人工没有评分就不能宣布通过最终验收。
可用 http://127.0.0.1:50435/blind-review.html?results=cloud-results 生成静态盲评页；每题四个版本顺序打散，评分仅保存在当前浏览器，可导出 human-brush-ratings.json。用户未评分时不可自动填分。
四张旧简笔画语义质量沿用原问题，不通过加粗宣称拥抱/送花语义已经改好。

七、下一步可能需要的真实素材
先让用户选择满意的笔触，不要求购买设备。2–3 张偏好的手绘曲线/圆圈/小人参考能帮助确定风格，但图片不能恢复真实笔压或速度。
可选用 capture.html 采集鼠标轨迹及时间；有触控笔时记录 x,y,time_ms,pressure、设备和 pointer_type。鼠标 pressure 标记 untrusted，不参与真实笔压分析。笔的 pressure 是设备报告的归一化值，不是校准后的力。
采集页只保存原始数据，不会自动把它接入当前合成压力候选。真实笔压标定是后续独立实验；本轮不训练压力模型。
