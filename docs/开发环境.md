# 开发环境说明（Unity + Blender）

本文说明本项目推荐的开发环境、软件版本、安装步骤与协作约定。目标：**个人或小团队能稳定地用 Unity 写玩法、用 Blender 做模型，并顺利导入与打包。**

---

## 1. 结论：推荐环境

| 用途 | 推荐选择 | 说明 |
|------|----------|------|
| 游戏引擎 / 主开发 | **Unity 6 LTS**（或 **Unity 2022.3 LTS**） | 主开发软件，锁定一个版本后不要随意升级 |
| 渲染管线 | **URP** | 适合独立 3D 项目，性能与扩展性平衡好 |
| 编程语言 | **C#** | Unity 官方标准 |
| 建模 / UV / 简单动画 | **Blender 4.2 LTS 或 4.x 最新稳定版** | 免费、与 Unity 管线成熟 |
| 代码编辑器 | **Visual Studio 2022**（Windows）或 **JetBrains Rider** | VS Code + C# Dev Kit 也可 |
| 版本管理 | **Git + Git LFS** | 模型、贴图、音频走 LFS |
| 操作系统 | **Windows 10/11 64-bit**（优先） | Unity 编辑与 Build 最省心；macOS 也可开发 |
| 硬件建议 | 见下文 | 保证 3D 场景编辑与预览流畅 |

> **选型理由**：Unity 生态完善、第三人称与物理开箱即用；Blender 免费且 FBX/glTF 导出成熟，适合学习与独立项目。两者组合是目前最常见、成本最低的 3D 游戏制作路径之一。

## 2. 硬件建议

| 级别 | CPU | 内存 | 显卡 | 磁盘 |
|------|-----|------|------|------|
| 最低可开发 | 四核以上 | 16 GB | 带独立显存或较强核显 | SSD 50 GB+ 可用空间 |
| 推荐 | 六核及以上 | 32 GB | NVIDIA / AMD 独立显卡（4 GB+ VRAM） | SSD 100 GB+ |

说明：

- Unity Editor + Blender 同时开时较吃内存，**16 GB 起步，32 GB 更舒适**
- 项目与 Library 缓存建议放在 **SSD**
- 笔记本需注意散热，长时间烘焙/导入时避免过热降频

## 4. 推荐安装与初始化步骤

### 4.1 安装 Unity

1. 安装 **Unity Hub** 并登录 Unity 账号（个人版 Personal 即可）
2. 在 Hub 中安装锁定的 Editor 版本（建议 **Unity 6 LTS**）
3. 勾选 Windows 打包模块与 IDE 支持
4. 新建项目时选择：**3D (URP)** 模板
5. 项目名建议：`3Dgame`，路径避免中文与空格

### 4.2 安装 Blender

1. 安装 Blender 4.x
2. 偏好设置建议：
   - 单位：Metric，Unit Scale = 1.0
   - 启用 FBX 导出（默认已有）
3. 建立个人资源库目录，例如：`ArtSource/`（可放在仓库外或仓库 `ArtSource/` 下，源 `.blend` 可用 LFS）

### 4.3 配置 Git

```bash
git lfs install
```

建议跟踪的大文件类型（`.gitattributes`）：

```gitattributes
*.fbx filter=lfs diff=lfs merge=lfs -text
*.blend filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
*.jpg filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.mp3 filter=lfs diff=lfs merge=lfs -text
*.tga filter=lfs diff=lfs merge=lfs -text
*.psd filter=lfs diff=lfs merge=lfs -text
```

Unity 必须忽略的目录（`.gitignore` 使用官方 Unity 模板）：

- `Library/`
- `Temp/`
- `Obj/`
- `Build/` / `Builds/`
- `Logs/`
- `UserSettings/`（按团队约定可忽略或提交部分）

### 4.4 Blender → Unity 最小工作流

1. Blender 中完成模型，**Apply Scale / Rotation**
2. 导出 FBX：
   - Scale = 1
   - Apply Transform（按需要）
   - 勾选需要的物体与动画
3. 将 FBX 放入 `Assets/Art/...`
4. Unity Inspector 中检查：
   - Scale Factor
   - Materials
   - Rig / Animation（角色）
5. 拖入场景，添加 Collider / Prefab 化

### 4.5 日常开发顺序建议

1. Unity 灰盒跑通移动与关卡逻辑
2. Blender 建模替换灰盒
3. 补交互、UI、音效
4. Build 测试

## 5. 本机目录约定（建议）

```text
3Dgame/                          # Git 仓库根目录
  docs/                          # 需求与环境文档
  ArtSource/                     # 可选：Blender 源文件（.blend）
  UnityProject/                  # Unity 工程根（或仓库根直接即工程）
    Assets/
    Packages/
    ProjectSettings/
```

若仓库根直接作为 Unity 工程，请保证 `Assets/`、`Packages/`、`ProjectSettings/` 在根目录，文档放在 `docs/`。

## 6. 环境兼容性说明

| 组合 | 是否推荐 | 说明 |
|------|----------|------|
| Windows + Unity + Blender | ✅ 最推荐 | 打包与驱动最省事 |
| macOS + Unity + Blender | ✅ 可开发 | 注意 Windows 包需在 Windows 或 CI 上打 |
| Linux + Unity | ⚠️ 可用但折腾 | Editor 支持有限，适合服务器 CI，不建议新手主力机 |
| 仅 Blender、无 Unity | ❌ | 无法完成游戏逻辑与发布 |
| Unreal 替代 Unity | 不在本项目范围 | 本项目明确以 Unity 为主 |

## 7. 团队 / 个人协作约定

1. **锁定 Unity 小版本**：在 README 写明 Exact Version（如 `6000.0.xxf1`）
2. **不要提交 `Library/`**
3. **模型命名规范**：`SM_` 静态网格、`SK_` 骨骼网格、`T_` 贴图、`M_` 材质、`P_` Prefab
4. **场景不要多人同时猛改同一 `.unity`**；可拆子场景（Additive）
5. 大改资源前先拉最新，避免 LFS 冲突难解
