# 开发环境说明（Unity + Blender）

本文说明本项目推荐的开发环境、软件版本、安装步骤与协作约定。目标：**个人或小团队能稳定地用 Unity 写玩法、用 Blender 做模型，并顺利导入与打包。**

---

## 1. 结论：推荐环境

| 用途 | 推荐选择 | 说明 |
|------|----------|------|
| 游戏引擎 / 主开发 | **Unity 6000.0.50f1（Unity 6 LTS）** | 已写入 `ProjectSettings/ProjectVersion.txt`，勿随意升级 |
| 渲染管线 | **URP** | `Packages/manifest.json` 已声明；首次打开可按向导生成 Pipeline Asset |
| 编程语言 | **C#** | Unity 官方标准 |
| 建模 / UV / 简单动画 | **Blender 4.2.9 LTS** | 仓库提供 Linux 安装脚本；Windows 请装官方 4.2 LTS |
| 代码编辑器 | **Visual Studio 2022**（Windows）或 **JetBrains Rider** | VS Code + C# Dev Kit 也可 |
| 版本管理 | **Git + Git LFS** | 模型、贴图、音频走 LFS |
| 操作系统 | **Windows 10/11 64-bit**（优先） | Unity 编辑与 Build 最省心；macOS 也可开发 |
| 硬件建议 | 见下文 | 保证 3D 场景编辑与预览流畅 |

> **选型理由**：Unity 生态完善、第三人称与物理开箱即用；Blender 免费且 FBX/glTF 导出成熟，适合学习与独立项目。两者组合是目前最常见、成本最低的 3D 游戏制作路径之一。

## 2. 硬件建议

| 级别 | CPU | 内存 | 显卡 | 磁盘 |
|------|-----|------|------|------|
| 最低可开发 | 四核以上 | 16 GB | 带独立显存或较强核显 | SSD 50 GB+ 可用空间 |
| 推荐 | 六核及以上 | 32 GB | NVIDIA / AMD 独立显卡（4 GB+ VRAM） | SSD 100 GB+ |

说明：

- Unity Editor + Blender 同时开时较吃内存，**16 GB 起步，32 GB 更舒适**
- 项目与 Library 缓存建议放在 **SSD**
- 笔记本需注意散热，长时间烘焙/导入时避免过热降频

## 4. 推荐安装与初始化步骤

> 仓库内 **Unity 工程骨架已创建**（`Assets/` / `Packages/` / `ProjectSettings/`），无需再 New Project。本机用 Hub **打开仓库根目录**即可。

### 4.1 安装 Unity（本机，Windows 优先）

1. 安装 **Unity Hub** 并登录（Personal 即可）
2. 安装 Editor **`6000.0.50f1`**
3. 勾选：Windows Build Support (IL2CPP)、Visual Studio / IDE 支持
4. Hub → **Open** → 选择本仓库根目录
5. 等待 Package 导入；若 Input System 提示重启，按提示操作
6. 若材质发粉红 / 未挂 URP：`Assets > Create > Rendering > URP Asset (with Universal Renderer)`，并在 Project Settings → Graphics 指定

也可先跑检查脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup/setup-windows.ps1
```

### 4.2 安装 Blender

**Windows / macOS**

1. 安装 Blender 4.2 LTS
2. 偏好设置：单位 Metric，Unit Scale = 1.0

**Linux（含本云环境）**

```bash
bash scripts/setup/install-blender-linux.sh
bash scripts/setup/verify-env.sh
```

源文件放在 `ArtSource/`，导出 FBX 到 `Assets/Art/`。

### 4.3 配置 Git

```bash
git lfs install
```

仓库已包含：

- `.gitattributes`（fbx / blend / 贴图 / 音频走 LFS）
- `.gitignore`（忽略 `Library/`、`Temp/`、`Build/` 等）

### 4.4 Blender → Unity 最小工作流

推荐用仓库脚本导出（轴向已按 Unity：Forward -Z / Up Y）：

```bash
blender --background ArtSource/Props/SM_Crate.blend \
  --python scripts/blender/export_fbx.py -- \
  --out ArtSource/Exports/SM_Crate.fbx
```

再把 FBX 放到 `Assets/Art/...`。示例道具 `Assets/Art/Props/SM_Crate.fbx` 已生成。

### 4.5 日常开发顺序建议

1. Unity 灰盒跑通移动与关卡逻辑（`PlayerController` / `CameraFollow` 已在 `Assets/Scripts`）
2. Blender 建模替换灰盒
3. 补交互、UI、音效
4. Build 测试

## 6. 环境兼容性说明

| 组合 | 是否推荐 | 说明 |
|------|----------|------|
| Windows + Unity + Blender | ✅ 最推荐 | 打包与驱动最省事 |
| macOS + Unity + Blender | ✅ 可开发 | 注意 Windows 包需在 Windows 或 CI 上打 |
| Linux + Unity | ⚠️ 可用但折腾 | Editor 支持有限，适合服务器 CI，不建议新手主力机 |
| 仅 Blender、无 Unity | ❌ | 无法完成游戏逻辑与发布 |
| Unreal 替代 Unity | 不在本项目范围 | 本项目明确以 Unity 为主 |

## 7. 团队 / 个人协作约定

1. **锁定 Unity 小版本**：在 README 写明 Exact Version（如 `6000.0.xxf1`）
2. **不要提交 `Library/`**
3. **模型命名规范**：`SM_` 静态网格、`SK_` 骨骼网格、`T_` 贴图、`M_` 材质、`P_` Prefab
4. **场景不要多人同时猛改同一 `.unity`**；可拆子场景（Additive）
5. 大改资源前先拉最新，避免 LFS 冲突难解
