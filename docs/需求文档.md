## 1. 项目概述

### 1.1 项目目标

开发一款可玩的 **第三人称 3D 探索冒险原型**，验证 Unity + Blender 完整工作流（建模 → 导入 → 关卡 → 玩法 → 打包），作为后续正式游戏的技术与内容底座。

### 1.2 产品定位

- **类型**：第三人称 3D 探索 / 轻量冒险
- **受众**：独立游戏学习与原型验证（个人或小团队）
- **风格**：低多边形（Low Poly）或简洁风格化，降低美术成本，便于 Blender 快速迭代
- **核心体验**：在 3D 场景中移动、观察、交互与完成简单目标

### 1.3 成功标准（MVP）

满足以下条件即视为第一版成功：

1. 玩家可控制角色在场景中流畅移动、跳跃、镜头跟随
2. 至少 1 个由 Blender 制作并导入 Unity 的完整可玩关卡
3. 至少 3 种可交互物体（如拾取物、机关、触发区域）
4. 有明确胜利 / 失败或通关条件
5. 可从 Unity 打包为可运行的 Windows 可执行程序

## 2. 功能需求

### 2.1 核心玩法（P0 — 必须）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| F-01 | 角色移动 | WASD / 手柄移动，含跳跃 | 移动手感稳定，无明显穿模或卡死 |
| F-02 | 镜头控制 | 第三人称跟随相机，鼠标/右摇杆旋转 | 镜头不穿墙（可用简单碰撞或遮挡淡出） |
| F-03 | 场景探索 | 可在关卡内自由探索 | 边界清晰，不会掉出地图 |
| F-04 | 物品拾取 | 靠近并拾取指定物品 | UI 或场景有拾取反馈 |
| F-05 | 目标系统 | 显示当前任务目标 | 完成目标后触发通关/胜利 |
| F-06 | 简单交互 | 开关门、按钮、触发机关 | 交互有动画或状态变化 |
| F-07 | 基础 UI | 开始菜单、暂停、HUD（目标提示） | 可开始游戏、暂停、退出 |

### 2.2 增强功能（P1 — 重要）

| ID | 功能 | 描述 |
|----|------|------|
| F-08 | 音效与 BGM | 脚步、拾取、胜利、背景音乐 |
| F-09 | 简单敌人 / 障碍 | 巡逻怪或陷阱，触碰扣血或重置 |
| F-10 | 生命值 / 检查点 | 掉落或受伤后从检查点重生 |
| F-11 | 收集品系统 | 收集物计数与结算展示 |
| F-12 | 设置面板 | 音量、鼠标灵敏度、画质 |

### 2.3 远期功能（P2 — 可选）

| ID | 功能 | 描述 |
|----|------|------|
| F-13 | 多关卡与关卡选择 | 2–3 个关卡串联 |
| F-14 | 存档读档 | 本地存档进度 |
| F-15 | 剧情对话 | 简单 NPC 对话或过场 |

## 3. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 目标机（中端 PC）稳定 60 FPS；场景 Draw Call / 面数可控 |
| 分辨率 | 支持 1920×1080；可窗口化 / 全屏 |
| 操作 | 键鼠为默认；预留 Input System 手柄映射 |
| 稳定性 | 无必现崩溃；掉落后可重生，不卡死 |
| 可维护性 | 脚本分模块（输入、角色、相机、交互、UI）；资源命名规范 |
| 资源管线 | Blender → FBX/glTF → Unity，材质与碰撞可复现 |

## 4. 美术与资源需求

### 4.1 建模（Blender）

| 资源类型 | 数量（MVP） | 说明 |
|----------|-------------|------|
| 玩家角色 | 1 | 带基础骨骼与 Idle / Walk / Jump 动画（或用占位人形） |
| 场景建筑 / 地形模块 | 5–15 | 地面、平台、墙、台阶、障碍物等可复用模块 |
| 可交互道具 | 3+ | 钥匙、箱子、按钮、门等 |
| 环境装饰 | 若干 | 树、石头、灯光道具等，控制面数 |
| 材质 / 贴图 | 配套 | 低多边形可用纯色材质或简单 Atlas |

### 4.2 导出规范

- 推荐导出格式：**FBX**（Unity 兼容性最好）或 **glTF 2.0**
- 单位：米（Blender 与 Unity 统一为 1 unit = 1 meter）
- 轴向方向：导出前确认 Forward / Up 轴与 Unity 一致（常见：Forward -Z，Up Y）
- 应用缩放（Apply Scale），避免导入后比例错误
- 碰撞：简单物体可在 Unity 中加 Collider；复杂碰撞可单独导出低模碰撞网格

### 4.3 UI / 音频

- UI：Unity UGUI 或 UI Toolkit，风格简洁即可
- 音频：可先用免费音效包；后续替换自制或授权资源

## 5. 技术架构

### 5.1 技术栈

| 层级 | 选型 |
|------|------|
| 引擎 | Unity **6000.0.50f1**（Unity 6 LTS） |
| 语言 | C# |
| 输入 | Unity Input System |
| 渲染 | URP（Universal Render Pipeline） |
| 物理 | Unity PhysX（CharacterController 或 Rigidbody） |
| 建模 | Blender 4.x |
| 版本管理 | Git + Git LFS（大资源） |
| IDE | Visual Studio / Rider / VS Code + C# 扩展 |

### 5.2 推荐工程目录

```text
Assets/
  Art/                 # 从 Blender 导入的模型、材质、贴图
    Characters/
    Environments/
    Props/
  Animations/
  Audio/
  Prefabs/
  Scenes/
    Boot.unity
    MainMenu.unity
    Level_01.unity
  Scripts/
    Player/
    Camera/
    Interaction/
    UI/
    Systems/
  Settings/            # URP、Input Actions 等
Packages/
ProjectSettings/
Docs/                  # 需求与环境文档（本仓库 docs/）
```

### 5.3 核心系统模块

1. **PlayerController**：移动、跳跃、重力
2. **CameraFollow**：第三人称跟随与遮挡处理
3. **Interactable**：交互接口（拾取、开关、触发）
4. **ObjectiveSystem**：任务目标与通关判定
5. **UIManager**：菜单、HUD、暂停
6. **GameState**：开始 / 游戏中 / 暂停 / 胜利 / 失败

## 6. 关卡设计（MVP）

### 6.1 Level_01 概述

一个小型封闭探索区域，目标示例：

> 收集 3 个能量碎片 → 打开终点大门 → 到达终点触发胜利

### 6.2 关卡要素

- 出生点与安全平台
- 需要跳跃的平台路径
- 1 个简单机关（踩压力板开门）
- 3 个收集物
- 终点区域与胜利触发器
- 掉落重置区（坠落回检查点）

## 7. 开发阶段

| 阶段 | 目标 | 主要产出 |
|------|------|----------|
| 阶段 0 | 环境搭建 | Unity 工程、Blender 安装、Git LFS、空场景可运行 |
| 阶段 1 | 灰盒原型 | 用 Unity 几何体完成移动、相机、基础关卡逻辑 |
| 阶段 2 | 美术替换 | Blender 建模导入，替换灰盒，整理 Prefab |
| 阶段 3 | 玩法完善 | 交互、目标、UI、音效 |
| 阶段 4 | 打磨打包 | Bug 修复、性能检查、Windows Build |

建议原则：**先灰盒跑通玩法，再替换美术**，避免过早陷入建模细节。

## 8. 风险与约束

| 风险 | 影响 | 应对 |
|------|------|------|
| 范围膨胀 | 做不完 | 严格按 P0 → P1 → P2 优先级 |
| 模型导入比例/轴向错误 | 反复返工 | 固定导出检查清单 |
| Unity 版本不一致 | 工程损坏 | 全项目锁定同一 Editor 版本 |
| 大文件撑爆 Git | 仓库难用 | 启用 Git LFS，忽略 Library/Temp 等 |
| 动画/骨骼复杂 | 进度受阻 | MVP 可用简单动画或 Asset Store 占位角色 |
